In diesem Kapitel werden Eigenschaften beschrieben, die sowohl für die <<rom.adoc#, ROM>>- als auch für die <<RAM.adoc#, RAM>>-Komponente gelten.

==== Verhalten

Eine Speicher-Komponente speichert Datenwerte, die bis zu 32 Bit lang sind. Die Anzahl der gespeicherten Datenwerte wird von der Breite der Adresse bestimmt, die im Attribut "Anzahl Bits in Adresse" definiert wird.

Mit dem Attribut "Inhalt anzeigen" kann gesteuert werden, ob die Speicher-Komponente ihren Speicherinhalt während der Simulation als Teil des Symbols anzeigen soll. Selbst wenn das Attribut gesetzt ist, wird der Speicherinhalt nur dann im Symbol angezeigt, wenn die Simulationsgeschwindigkeit höchstens im Bereich "Beobachten" ist - im schnellsten Bereich "Verwenden" wird der Speicherinhalt nie angezeigt. Für eine Erklärung der Simulationsgeschwindigkeiten siehe das Kapitel <<../simulation/simulation.adoc#, Simulation>>.

==== Speicherinhalt importieren und exportieren

Ein Doppelklick auf eine Speicherkomponente öffnet einen Dialog, mit dem der Speicherinhalt aus einer Datei importiert (nur ROM) und in eine Datei exportiert werden kann. Zudem kann der Speicherinhalt zurückgesetzt werden, d.h. alle Speicherzellen werden auf den Wert 0 gesetzt.

Dadurch hast Du die Möglichkeit, den Inhalt einer Speicher-Komponente in einem beliebigen Editor zu schreiben, als Datei zu speichern, und dann in die Speicher-Komponente zu importieren. Der importierte Speicherinhalt wird dadurch Bestandteil der Speicher-Komponente und wird in die Schaltungs-Datei aufgenommen, wenn die Schaltung gespeichert wird; die Datei, aus der der Speicherinhalt geladen wurde, wird dann nicht mehr benötigt. Das Format der Datei, aus der Speicherinhalte importiert werden können, wird weiter unten beschrieben.

Beim Exportieren des Speicherinhalts in eine Datei wird in der aktuellen Version von Antares immer das Datei-Format "Standard" verwendet (siehe unten).

==== Datei-Format "Standard"

Das Format der Datei, aus dem die Daten einer Speicher-Komponente importiert werden können, ist bewusst so einfach gestaltet, dass die Daten mit einem beliebigen Text-Editor geschrieben werden können.

Die Daten in der Datei bestehen im wesentlichen aus einer Folge von hexadezimalen Werten, die entweder durch ein Leerzeichen oder einen Zeilenumbruch getrennt sind, wobei beide Trennarten in derselben Datei beliebig gemischt vorkommen können. Damit können z.B. jeweils 8 Bytes auf einer Zeile zusammengefasst werden.

Die Länge des hexadezimalen Wertes wird durch das Attribut "Anzahl Bits in Daten" bestimmt: z.B. haben Daten für einen 8-Bit-Speicher die Form "FF". Dabei akzeptiert Antares sowohl Grossbuchstaben als auch Kleinbuchstaben als hexadezimale Daten.

.Beispiel mit Leerzeichen und Zeilenumbruch
----
1F 7E 05 B8
45 A0
----

Das Datei-Format beinhaltet kein "run-length Encoding". Längere Datenabschnitte, die an jeder Adresse denselben Wert haben, müssen diese Werte explizit enthalten. Eine Ausnahme stellen abschliessende 0-Werte dar, die nicht explizit vorkommen müssen. Wenn eine Datei mit obenstehendem Beispiel-Inhalt in einen 8-Bit-Speicher mit 256 Datenzellen geladen wird, werden die ersten 6 Byte mit den Daten aus der Datei gesetzt und die restlichen 250 Datenzellen auf den Wert 0 gesetzt. Die abschliessenden 0-Werte müssen also nicht in der Datei vorkommen.

Dasselbe gilt für das Speichern von Dateien. Antares speichern nur "effektiv relevante" Daten. Im obenstehenden Beispiel stellt Antares nach dem Schreiben des letzten A0-Bytes fest, dass danach nur noch 0-Werte kommen, und verzichtet darauf, diese 0-Werte in die Datei zu schreiben.

Speicherzellen können einen optionalen Kommentar enthalten, der in der separaten Inhaltsansicht angezeigt wird, falls als Anzeige-Layout "1 Spalte" gewählt wird. Kommentare werden in der Datei durch einen Doppelpunkt vom Datenwert getrennt.

.Beispiel Kommentare
----
1F:Kommentar 7E 05:Kommentar2 B8
45:Kommentar3 A0
----

Da Leerzeichen zur Trennung von Datenzellen und Doppelpunkte zur Trenning von Daten und Kommentaren verwendet werden, müssen diese beiden Zeichen speziell behandelt werden, wenn sie in Kommentaren vorkommen. Dazu wird ein sog. "Escaping" mit Hilfe des \-Zeichens (Backslash) verwendet.

.Beispiel Kommentar mit Escaping
----
1F:Dies\ ist\ ein\ Kommentar 7E 05:Kommentar\ mit\ \: B8
45:Kommentar \3 A0
----

==== Datei-Format "Einzelzeilen"

Das Datei-Format "Standard" eignet sich nicht sehr gut für die Bearbeitung in einem Editor, wenn viele Kommentare vorkommen. Dies ist z.B. dann der Fall, wenn das Datei ein Maschinenprogramm enthält, das in die ROM-Komponente einer Mikroprozessor-Schaltung geladen werden soll. Solche Dateien können in jeder Zeile einen Kommentar mit Leerzeichen enthalten.

Zu diesem Zweck unterstützt Antares ein zweites Datei-Format, bei dem jeder Datenwert inkl. Kommentar auf einer eigenen Zeile steht. Dadurch ist es bei diesem Datei-Format nicht nötig, Leerzeichen und Doppelpunkte zu escapen.

.Beispiel Einzelzeilen
----
#amd-nl-0.1
7000:Initialize I at 0800
1800
7065:Initialize L at 0801
1801
7000:Initialize S at 0802
1802
7001:Initialize ONE at 0803
1803
0801:IF (I == L) THEN GOTO END
3800
5013
0802:S = S + I
2800
1802
1FFE:Output S
0800:I = I + 1
2803
1800
6008:GOTO LOOP
FF00:Stop program
----

Damit Antares beim Laden einer Datei erkennt, um welches Format es sich handelt, muss auf der ersten Zeile die Format-Kennung **amd-nl-0.1** vorkommen ("amd": Antares Memory Dump, "nl": Newline, 0.1: Versionsnummer des Formats).

NOTE:: Die ensprechende Format-Kennung des Formats "Standard" ist **amd-df-0.1**. Sie ist optional. Wenn Antares in einer zu ladenden Speicher-Datei keine Format-Kennung findet, wird die Datei als Standard-Format interpretiert.

==== Speicherinhalt im Symbol anzeigen

Mit dem Attribut "Inhalt anzeigen" kann gesteuert werden, ob ein Teil des Speicherinhalts innerhalb des Symbols angezeigt werden soll. Während der Simulation zeigt Antares den Speicherinhalt in der Region der aktuellen Adresse an und hebt die Speicherzelle hervor, die adressiert ist. Kommentare werden nicht angezeigt.

==== Speicherinhalt separat anzeigen

Zusätzlich zur Anzeige des Speicherinhalts im Symbol kann der Speicherinhalt auch separat angezeigt werden. Ein Doppelklick auf eine Speicher-Komponente öffnet einen Dialog, der den Speicherinhalt anzeigt. Im Auswahlfeld "Layout" kann gewählt werden, wieviele Spalten in einer Zeile angezeigt werden. Kommentare werden nur im Layout "1 Spalte" dargestellt.

Bei Doppelklick mit gedrückter ALT-Taste wird dieselbe Ansicht als Unteransicht im Hauptfenster dargestellt. Dies kann nützlich sein, wenn der Inhalt mehrerer Speicher-Komponenten gleichzeitig dargestellt werden soll.

==== Attribute

Ausrichtung:: Die Himmelsrichtung, in die der Datenanschluss zeigt.

Anzahl Bits in Adresse:: Die Anzahl Bits, aus denen die Adressen der Speicherkomponente besteht. Dies bestimmt die Anzahl Speicherzellen der Speicherkomponente.

Anzahl Bits in Daten:: Die Bitbreite jeder einzelnen Speicherzelle.

Inhalt anzeigen:: Bestimmt, ob der Speicherinhalt innerhalb des Symbols angezeigt werden soll.

Anzahl Inhalts-Zeilen:: Kann nur gesetzt werden, wenn "Inhalt anzeigen" ausgewählt ist. Bestimmt die Anzahl Zeilen der Speicherinhalts-Anzeige innerhalb des Symbols.

Anzahl Inhalts-Spalten:: Kann nur gesetzt werden, wenn "Inhalt anzeigen" ausgewählt ist. Bestimmt die Anzahl Spalten der Speicherinhalts-Anzeige innerhalb des Symbols.
